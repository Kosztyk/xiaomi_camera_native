# IMILAB outdoor PTZ ipc020

Xiaomi Camera Native v0.3.14 supports local video and optional horizontal
pan for the China-region IMILAB outdoor PTZ, model
`chuangmi.camera.ipc020`. Home Assistant streams video over direct TUTK/UDP.
The camera can pan left and right. Each button press sends one movement step.

## Setup

1. Install or update Xiaomi Camera Native and restart Home Assistant.
2. Select the camera from the region where it is registered in Mi Home. The
   tested camera uses **China (`cn`)**.
3. Go to **Settings → Devices & services → Xiaomi Camera Native → Options →
   Configure a camera** and select the `ipc020`. Check the camera's local IPv4
   address and turn on **Use TUTK LAN transport (ipc020)**.
4. Start with **HD** quality and **H.264** output to match the tested setup.
   Turn on **Enable horizontal pan (ipc020)** if you want movement controls.
5. Save, open the camera in a fresh browser tab or reopen the Companion app,
   and wait for live video. With pan enabled, the popup and device page offer
   only Left and Right. The arrows enable when `pan_tilt_ready` is true.

Both options are off by default. Upgrading from the beta preserves saved
options and removes any obsolete `ipc020` Tilt Up and Tilt Down entities.
The camera and Home Assistant need local network connectivity. The first
TUTK packet goes to the camera's UDP port 32761. Xiaomi's cloud provides
per-connection credentials.

## Hardware verification

| Item | Observed result |
| --- | --- |
| Physical device | IMILAB outdoor PTZ, `chuangmi.camera.ipc020`, firmware `4.0.9_0102`, China region |
| Tested build | Xiaomi Camera Native `v0.3.14b5` |
| Connection | Signed authentication, direct TUTK/18 over UDP |
| Video | H.265 source, H.264 output, HD quality |
| Device buttons | Three successful physical steps in each direction |
| Popup | Only Left and Right visible, both moved the camera during live video |
| Live-session requirement | An idle press was refused, and pan became ready after video arrived |

One tester provided these results on TUTK/18. The TUTK 25+ sequence recovery
in v0.3.14 was checked with synthetic packet loss and rollover. Other
firmware and SDK variants need device testing.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Xiaomi rejects MISS provisioning with code `-6` | Enable **Use TUTK LAN transport (ipc020)**. The TUTK path requests its own credentials. |
| Connection stops at `lan_discovery` or `lan_handshake` | Verify the camera's local IP and make sure Home Assistant can reach it on the LAN. |
| Connection reaches `waiting_for_video` | Check `ipc020_tutk_media_results` and `ipc020_tutk_video_packets`. Try HD with H.264 output. |
| Pan asks you to open live view | Open the stream, wait for video and check `pan_tilt_ready`. Pan uses the current video session. |
| Old gray tilt arrows still appear after upgrading | Refresh the page or reopen the Home Assistant app to load the current script. |
| Pan press times out | Check `ipc020_tutk_ptz_ack_state` and `last_ptz_error`. Observe the camera before making another press. |

If the IP changes, **Automatically update camera IP** tries matching router
trackers and Xiaomi cloud discovery. The integration saves a candidate
address after the camera handshake succeeds. Turn automatic updates off if
you use a fixed address.

## Diagnostic fields

Use the camera's state attributes or the integration's downloaded diagnostics.

| Field | Meaning |
| --- | --- |
| `ipc020_tutk_stage` | Latest provisioning, connection, media or streaming stage. |
| `ipc020_tutk_auth_mode`, `ipc020_tutk_sdk` | Authentication mode and SDK version reported by the peer. |
| `ipc020_tutk_media_results` | Audio, video and quality negotiation ACK results. The integration exposes video only. |
| `ipc020_tutk_video_packets`, `ipc020_tutk_dropped_packets`, `ipc020_tutk_malformed_packets` | Packet reception counters for the current TUTK session. |
| `frames_received`, `reconnects`, `last_error` | Source frames, reconnection attempts and last session error. Diagnostics call the frame counter `frames`. |
| `pan_tilt_directions`, `pan_tilt_ready`, `last_ptz_error` | Allowed directions, readiness to move and latest movement error. |
| `ipc020_tutk_ptz_ack_state`, `ipc020_tutk_ptz_ack_ms` | Transport ACK status and time in milliseconds. |
| `ipc020_tutk_ptz_command_seq`, `ipc020_tutk_ptz_unmatched_acks`, `ipc020_tutk_ptz_app_responses` | Motor command sequence and counts of unmatched ACKs and recognized app responses. |

A matched ACK confirms receipt of the command. Observe the camera to confirm
movement. The integration sends each motor press once, since a command can
move the camera even if the ACK is lost.

For a bug report, include the camera model, firmware, region, integration
version, Home Assistant version and relevant diagnostics. Remove account
tokens, P2P credentials, keys and private addresses before posting.
